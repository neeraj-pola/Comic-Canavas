# CLAUDE.md — Comic Canvas

> A diary that draws itself. Speak or type your day → a four-panel comic with you in it → two taps a day teach it your taste.
> This file is the single source of truth for building the project. Work top to bottom. Do not start a phase until every task in the previous phase is checked and its gate passes. Deployment is Phase 12 and happens once, at the end.

---

## 0. How to work in this repo

### 0.1 Ground rules for Claude Code (and humans)

- **Backend first.** Phases 1–9 produce a fully tested backend running locally with mock image generation. The frontend (Phase 10) is wired to it afterward. The final visual design is fixed: `design/comiccanvas-landing.html` and `design/comiccanvas-dashboard.html` are the reference; do not invent new UI.
- **Contracts before code.** Every module boundary is a Pydantic model in `packages/contracts`. Change the contract first, then the code, then the tests.
- **Provider-agnostic LLM calls.** Every LLM call goes through `llm.complete()` / `llm.structured()` (Phase 1). Never import `anthropic` or `openai` outside `services/worker/app/llm/`. Switching provider is an environment variable.
- **No deploys mid-build.** Everything runs locally (`make dev`) until Phase 12. No Docker: local dev uses a native local Postgres (pgvector enabled, ADR 0009 — not a Supabase project, see ADR 0017), a local Redis, and a filesystem storage adapter. Only Neon/Clerk (ADR 0017) and LLM/ASR/image API keys are needed before Phase 12; Railway, Vercel, R2, Modal accounts come in Phase 12.
- **Golden sets are frozen.** Files under `ml/goldens/` change only via a PR titled `golden:` with a reason.
- **Every task has an acceptance test.** A task is done when its `Accept:` line is true, not when the code exists.
- **Log cost.** Every external call (LLM, ASR, image) records `provider, model, tokens/units, usd` to the `cost_events` table.
- **Small commits, conventional messages.** `feat(extractor): …`, `fix(critic): …`, `test(api): …`, `docs(adr): …`.
- **Write an ADR** (`docs/adr/NNNN-title.md`) whenever choosing between alternatives that were discussed in this file. Ten lines is enough.

### 0.2 Commands (fill in as they are created)

```bash
make dev          # starts api (uvicorn --reload), worker (arq), scheduler (dev loop) via honcho/Procfile; expects local redis + DATABASE_URL
make test         # unit + integration (mock providers)
make test-live    # runs golden sets against real LLM providers (costs money, prints spend)
make eval         # ml/evals: extractor recall, critic accuracy, reward-model held-out
make lint         # ruff + mypy --strict + eslint
make migrate      # alembic upgrade head
make seed         # loads fixtures: one user, 7 days, cast of 3
```

### 0.3 Definition of done (applies to every task)

1. Code + types (`mypy --strict` clean for Python, `tsc --noEmit` clean for TS).
2. Unit test with recorded provider responses (VCR cassette in `tests/cassettes/`); tests use a dedicated `comiccanvas_test` schema so they never touch dev data.
3. Acceptance line in this file verified and the checkbox ticked with the date.
4. If a decision was made, an ADR exists.
5. `make test` green.

```

│  Web (Next)  │ ───────────▶ │  API FastAPI │ ─────▶ │  Worker (arq) runs LangGraph   │
│  Vercel      │ ◀─── SSE ─── │  Railway     │        │  ingest→beats→script→prompts→  │
└──────────────┘              └──────┬───────┘        │  generate→critic→compose→memory │
                                     │                └──────┬──────────┬─────────────┘
                        Clerk Auth ──┘                       │          │
                                                      Postgres+pgvector  R2 (media)
                                                             │
                                          Scheduler (cron): reminders, weekly recap,
                                          feedback export → Modal training → eval gate → registry
```

**Pipeline nodes (fixed contracts, see §3):** 0 Identity onboarding · 1 Input · 2 ASR · 3 Beat extractor · 4 Script agent · 5 Prompt writer · 6 Panel generator · 7 Consistency critic · 8 Composer · 9 Feedback · 10 Memory · 11 Weekly training · 12 Eval gate.

**Decisions already made (do not reopen without an ADR):**

| Area | Decision |
|---|---|
| Orchestration | LangGraph, one `DayState` object, fan-out for panels |
| LLM | Provider layer supporting **Anthropic Claude** and **OpenAI** with identical interface; default extractor = `gpt-4o-mini` (cheap, literal), default script = `claude-sonnet` or `gpt-4o` (A/B in Phase 11) |
| ASR | Groq `whisper-large-v3-turbo`, `faster-whisper` CPU fallback, no fine-tuning |
| Images | Hybrid: **Leonardo Phoenix + Character Reference** (production) and **Flux Dev + identity LoRA on fal.ai/Modal** (learning track). `MockImageProvider` for all tests |
| Critic | ArcFace (identity) + DINOv2-small (style) + SigLIP (alignment) + Bradley–Terry head; ONNX on CPU |
| Style | Simple characters, detailed environments (two-layer prompts); no artist names in prompts |
| Preference learning | Reward model → DPO (script) → GRPO (prompt writer, critic reward) → Diffusion-DPO (Flux LoRA). No PPO |
| Auth | **Clerk** email + password (ADR 0017, replacing Supabase Auth — free-tier limit hit); API verifies Clerk JWT |
| DB | Postgres + pgvector (native local Postgres in dev, ADR 0009; **Neon** in prod, ADR 0017 — replacing Supabase/Railway, both real free-tier dead ends); `bge-small-en-v1.5` embeddings on CPU |
| Media | Cloudflare R2 in production; `LocalFileStorage` adapter in dev (same `Storage` interface) |
| Training/serving GPU | Modal (scale-to-zero) |
| Frontend | Next.js 15 + Tailwind, design tokens from the prototypes; Inter + JetBrains Mono; mustard `#E9D24A` accent; mustard diary cover |
| PDF | Weekly recap rendered server-side with Playwright from the same HTML template used by the dashboard print view |

## 3. Contracts (write these first, Phase 1)

```python
# packages/contracts/day.py
class Beat(BaseModel):
    id: str
    time: Literal["morning","midday","afternoon","evening","night","unknown"]
    place: Literal["bedroom","desk","kitchen","gym","outdoors","transit","cafe","other"]
    place_detail: str | None          # "small kitchen with a window", used for environment prompts
    event: str = Field(max_length=200)
    emotion: str
    people: list[str] = []
    objects: list[str] = []
    importance: float = Field(ge=0, le=1)
    humor: float = Field(ge=0, le=1)
    quote: str | None                  # verbatim from transcript or None

class BeatSheet(BaseModel):
    date: date
    mood_arc: list[str] = Field(min_length=1, max_length=6)
    beats: list[Beat] = Field(min_length=1, max_length=6)
    people_mentioned: list[str]
    flags: list[Literal["too_short","sensitive","no_events"]]

class Panel(BaseModel):
    id: int                            # 1..4 (or 1..2 on quiet days)
    beat_id: str
    place: str; time_of_day: str
    expression: Literal["happy","content","sad","panic","angry","tired","surprised","neutral"]
    action: str                        # one visual sentence
    framing: Literal["wide","medium","close"]
    caption_a: str = Field(max_length=60)
    caption_b: str = Field(max_length=60)
    bubble: str = Field(max_length=20, default="")
    cast: list[str] = []               # person ids in frame

class Script(BaseModel):
    mood: str
    quiet_day: bool
    panels: list[Panel] = Field(min_length=2, max_length=4)

class ImagePrompt(BaseModel):
    panel_id: int
    generator: Literal["leonardo","flux","mock"]
    character_clause: str              # short, fixed, from look card
    environment_clause: str            # long, detailed: props, materials, lighting, texture
    positive: str                      # assembled
    negative: str
    seed: int | None
    guidance: float | None
    steps: int | None

class Candidate(BaseModel):
    id: str; panel_id: int; url: str; seed: int
    scores: dict[str, float] = {}      # identity, style, alignment, detail, reward
    face_box: tuple[int,int,int,int] | None
    chosen: bool = False
    rejected_reason: str | None

class DayState(BaseModel):            # the LangGraph state
    job_id: str; user_id: str; date: date
    source: Literal["text","audio"]
    text: str | None; audio_url: str | None
    transcript: str | None
    beats: BeatSheet | None
    script: Script | None
    prompts: list[ImagePrompt] = []
    candidates: list[Candidate] = []
    retries: dict[int,int] = {}
    strip_url: str | None; layout: dict | None
    cost_usd: float = 0.0
    errors: list[str] = []
    versions: dict[str,str] = {}       # prompt/model/checkpoint versions used
```

```python

class Thumb(BaseModel):       day_id: str; panel_id: int; value: Literal[1,-1]
```

41. **Ratings as well as picks, and Feel-Good Thompson Sampling for dueling bandits (user request 2026-09-21).**
    - **Ratings** (`off / ok / great`, one per image, usually the one in the strip): a pick says which of three is best but never whether ANY is good; a rating does.     - **Feel-Good Thompson Sampling for dueling bandits** (`preference/bandit.py`; Li et al., ICML 2024, arXiv 2404.06013 — read via a summary of the paper, formulas as reported there): two parameters drawn **independently** from a tempered posterior (likelihood weight `eta = 0.25`), each takes its best arm, no constraint that they differ; a feel-good term `mu * max_a' <theta, phi(a') - phi(a_i^{3-j})>` rewards parameters that see a strong arm. It now chooses each panel's three settings once the knob model has 10 picks: option 0 = the best guess (posterior-mean best arm), options 1 and 2 = the best arm of each draw (so options can differ on several knobs, e.g. "cooler + closer"; the picker labels them by the knobs they move relative to the guess); duplicates are replaced by the old one-knob steps; deterministic per job and panel; `IMAGE_OPTIONS=structured` reverts. Arms = the 27 settings within one level of the guess; draws = tempered-Laplace Gaussian, importance-reweighted by the feel-good term.
    - **About "with guarantees", stated plainly.** The paper proves regret `O~(d sqrt(T))`, nearly minimax-optimal, for a linear utility, the sigmoid link, bounded features, and exact posterior sampling (it uses SGLD). Ours approximates that: Laplace + importance reweighting instead of exact/SGLD draws; a moving 27-arm set instead of the full arm set; a best-of-3 pick rank-broken into pairs instead of one pair per round; old picks forgotten; and the third option is our own best guess. **So the bound is motivation, not a promise for this system.** What was checked is behaviour: **simulation (production code; 60 people x 100 picks each; regret = best of all 125 settings minus the utility of the option picked; lower is better)** — strong sweet-spot: today's design 0.69 -> dueling TS 0.54 (final best guess 0.34 -> 0.21); mild sweet-spot 0.48 -> 0.40; monotone taste 2.11 -> 1.35; no taste 0.00 everywhere. **The feel-good term itself gave no measurable gain**: mu 0.005-0.02 matched plain tempered TS, 0.1 was worse on regret (better on the final guess only for the strong case) — the improvement comes from the tempered two-draw design, so mu is set to a small 0.005 to stay faithful to the algorithm without pretending it matters. The paper's own mu (`1/(10 e^B sqrt(T))`) is ~0 at any realistic B.

## 7. Provider layer — reference design (Phase 1)

```python
# services/worker/app/llm/base.py
class Message(TypedDict): role: Literal["system","user","assistant"]; content: str | list[ContentPart]
class LLMResult(BaseModel): text: str; input_tokens: int; output_tokens: int; usd: float; provider: str; model: str; latency_ms: int

class LLMProvider(Protocol):
    name: str
    async def complete(self, messages: list[Message], *, model: str, temperature: float = 0, max_tokens: int = 1024) -> LLMResult: ...
    async def structured(self, messages: list[Message], schema: type[T], *, model: str, temperature: float = 0, retries: int = 1) -> tuple[T, LLMResult]: ...

# routing
def resolve(role: str) -> tuple[LLMProvider, str]:
    spec = os.environ[f"LLM_{role.upper()}"]          # "anthropic:claude-sonnet-4-6" | "openai:gpt-4o-mini" | "openai_compat:http://host/v1|model"
    provider_name, model = spec.split(":", 1)
    return PROVIDERS[provider_name], model

# usage inside a node (never import SDKs here)
provider, model = resolve("extractor")
sheet, meta = await provider.structured(msgs, BeatSheet, model=model)
state.cost_usd += meta.usd; state.versions["extractor_model"] = f"{meta.provider}:{meta.model}"
```

Structured output mapping: Anthropic → single forced tool with the schema; OpenAI → `response_format: json_schema, strict: true`; `openai_compat` (vLLM on Modal for the DPO'd writer) → same as OpenAI with `base_url`. Both providers must pass the same contract tests in `tests/unit/llm/test_parity.py`.
